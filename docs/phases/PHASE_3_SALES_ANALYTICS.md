# Phase 3 Specification: Sales Analytics Engine & Sales Tool

## 🎯 End Goal
Build a quantitative Pandas analytics pipeline for Sales CSV datasets. The pipeline validates CSV schemas, calculates exact numerical KPIs (revenue trends, product line performance, regional breakdowns, deal velocity), persists raw rows and computed summary metrics into PostgreSQL, and exposes an independent `SalesAnalyticsTool`.

---

## 🛠️ Sub-Phases & Deliverables

### Sub-Phase 3.1: Sales CSV Schema Validation & Processing Service
- File: `backend/services/csv_service.py`
- Functions:
  - `validate_sales_csv(df: pd.DataFrame) -> bool`: Checks for required columns (`Date`, `Product`, `Region`, `Revenue`, `Units`, `SalesRep`).
  - `clean_sales_data(df: pd.DataFrame) -> pd.DataFrame`: Handles missing values, formats dates, converts revenue and unit counts to numeric types.

### Sub-Phase 3.2: Pandas Quantitative Sales Analytics Engine
- File: `backend/services/csv_service.py`
- Calculations performed purely in Python (Zero LLM involvement):
  - Total Revenue & Growth Rate (YoY / MoM).
  - Product line revenue distribution (top performing vs. declining product lines).
  - Regional sales performance & sales rep deal velocity.
  - Average Deal Size & Sales Volume trends.

### Sub-Phase 3.3: PostgreSQL Database Persistence
- File: `backend/models/db_models.py`
  - SQLAlchemy model `SalesTransaction`: Stores raw validated transaction records.
  - SQLAlchemy model `SalesAnalyticsSummary`: Stores pre-computed summary metrics (total revenue, product revenue breakdown, regional metrics).
- File: `backend/services/csv_service.py`
  - Write validated data to PostgreSQL via SQLAlchemy session.

### Sub-Phase 3.4: Sales Analytics Tool Implementation
- File: `backend/tools/sales_tool.py`
- Class `SalesAnalyticsTool(BaseTool)`:
  - Input: Analytical query or metric request (e.g. `"revenue_trends"`, `"product_performance"`).
  - Action: Queries PostgreSQL summary tables / runs Pandas aggregations over stored sales data.
  - Output: Returns list of normalized `EvidenceItem` objects ONLY.
  - `EvidenceItem` format:
    - `source`: `"Sales Analytics Tool"`
    - `category`: `"Quantitative Metric"`
    - `title`: Metric title (e.g., `"Quarterly Revenue Performance"`)
    - `details`: `{"total_revenue": float, "growth_rate_pct": float, "top_product": str, "regional_breakdown": dict}`
    - `confidence`: `"High (100% Deterministic Python Calculation)"`

### Sub-Phase 3.5: Sales CSV Upload API Endpoint
- File: `backend/api/upload.py`
- Endpoint: `POST /api/upload/sales`
  - Accepts Sales CSV file.
  - Triggers validation, Pandas analytics calculations, and PostgreSQL persistence.
  - Returns `{"status": "success", "rows_processed": int, "total_revenue": float}`.

---

## 🔍 Verification Criteria
1. Uploading sample Sales CSV via `POST /api/upload/sales` succeeds and populates PostgreSQL tables.
2. Executing `SalesAnalyticsTool.execute()` returns exact numeric metrics generated by Pandas.
3. Zero LLM math or hallucinated numbers exist in tool outputs.
